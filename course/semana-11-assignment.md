# Assignment Semana 11. ADR para una decisión de SkillHub

## Propósito

Convertir una decisión pendiente de SkillHub en un registro arquitectónico explícito, trazable y revisable.

## Entregable

Crea `course/semana-11-adr.md` usando una decisión pendiente de producto, como el contrato del sistema de empleados, la entrega de notificaciones, el almacenamiento de documentos o la corrección de cursos publicados. El ADR debe incluir estado, contexto, decision drivers, alternativas, restricciones, supuestos, decisión, consecuencias, principios aplicables, riesgos, deuda técnica y reversibilidad.

Indica si la decisión es de una o dos vías, qué evidencia falta, quién debe validarla y qué métrica, fecha o evento provocaría una revisión o reemplazo del ADR.

## Criterios de aceptación

- El problema y el alcance de la decisión son concretos.
- Las alternativas son viables y se comparan con los mismos drivers.
- Se distinguen restricciones de supuestos y se indica cómo validar los supuestos importantes.
- Las consecuencias incluyen al menos un beneficio, un costo y un riesgo residual.
- Se identifica deuda técnica, reversibilidad y el criterio para revisar la decisión.
- El documento permite entender la decisión sin consultar conversaciones externas.

## Fuera de alcance

No implementes la alternativa ni redactes ADRs para varias decisiones. El resultado esperado es un único registro listo para revisión con el equipo del producto.
